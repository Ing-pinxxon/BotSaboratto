1. Cliente envía mensaje WhatsApp

El cliente escribe desde WhatsApp. Puede ser un mensaje largo enviado en varios fragmentos rápidos (tipeo por palabras).

Meta Cloud API Kapso Webhook
🔄

2. POST /webhook — Parser dual

El servidor recibe el HTTP POST. El parser detecta automáticamente si el formato es Meta Cloud API o Kapso, extrae texto, número y nombre del remitente.

src/routes/webhook.js src/middleware/validation.js
⏱️

3. MessageBuffer — Acumulación 10s

El mensaje se añade al buffer del usuario. El timer de 10 segundos se reinicia con cada nuevo fragmento. Esto agrupa mensajes enviados rápido uno tras otro antes de procesar.

src/utils/buffer.js debounceMs: 10000
🔍

4. processBuffer() — Chequeos previos al AI

Después del silencio de 10s, se ejecutan validaciones en orden. El flujo se corta en el primer caso que aplique.

Caso A — ¿Ya confirmó pedido hoy?
SI → Ignorar silenciosamente (bloqueo diario)
NO → continúa →
Caso B — ¿Es una confirmación corta? (≤30 chars, "ok/sí/listo/dale/de una...")
SI → Enviar cierre + bloquear usuario hoy
NO → continúa →
config/bot.config.js userState Map
🕐

5. schedule.service.js — ¿Abierto o cerrado?

Se consulta la hora actual en America/Bogota y el horario semanal configurado. El resultado determina qué prompt de AI se carga.

Resultado:
OPEN → carga skills/open.md (menú completo + reglas)
CLOSED → carga skills/closed.md + inyecta próx. apertura
src/services/schedule.service.js config/skills/
🤖

6. ai.service.js — Google Gemini

Se crea una sesión de chat Gemini con el historial de conversación del usuario (máx 60 entradas). El skill open/closed actúa como system instruction. Gemini genera la respuesta.

src/services/ai.service.js gemini-2.5-flash-lite ChatHistory
📤

La respuesta de Gemini se envía al cliente. El servicio selecciona automáticamente el proveedor disponible según las variables de entorno.

8. Actualizar historial + detectar estado

El par usuario/modelo se guarda en ChatHistory. Luego se revisa si la respuesta del AI contiene "Total:" — la señal de que el bot presentó un resumen completo de pedido.

¿Respuesta contiene "Total:"?
SI → pendingConfirmation = true
NO → sin cambio de estado
src/utils/history.js userState.pendingConfirmation
🍳

9. hooks.js — ¿Reenviar a la cocina?

Solo si el bot está ABIERTO: se evalúa si la respuesta debe llegar a la cocina. Se revisa que contenga "Total:" y que el mensaje del usuario NO sea una simple confirmación.

shouldForward() == true?
SI → buildForwardMessage() → WhatsApp KITCHEN_NUMBER
NO → flujo termina aquí
config/hooks.js KITCHEN_NUMBER (env)
💳

Flujo paralelo — Notificación de pago

Independiente del flujo de pedido: la automatización externa (Zapier / MacroDroid) detecta un pago en Nequi / Daviplata / Bre-B y hace un POST a /notify-payment. El bot formatea y envía confirmación al número de pagos.

POST /notify-payment src/routes/payments.js BOLD_NOTIFY_NUMBER (env)
